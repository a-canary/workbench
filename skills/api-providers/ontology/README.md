# LLM Ontology

The single map of every LLM policy, routing rule, host, and endpoint in the arc system.
Broken into topics; each file is the authority for its layer.

## The chain (top to bottom)

```
consumer (agent profile / cron / pi / curl)
  → alias (planning|hard|easy|bench|driver|hygiene, or pool: smart|fast|…)
    → router (arc-llm-proxy :8091  |  cli-proxy :7890  |  direct API)
      → host (103 GPU box | 159 operator | 100.73.201.58 | cloudflare/Veles | public APIs)
        → model (Bonsai-27B | Qwen3.8-27B | DeepSeek-V4-Flash | MiniMax-M3 | …)
```

## Known defects (as of 2026-08-25)

1. **Ghost alias `minimax-build`** — referenced by 3 worker profiles, absent from `arc-agents/config.json`. Loader silently falls back to `default_alias` (`planning`), masking the breakage in ledger events. See [03-aliases.md](03-aliases.md).
2. **Single-endpoint switchboard** — all 6 arc-proxy aliases route to `103:1234` (Bonsai-27B). When 103 is down, the entire factory LLM lane is down. No failover to Veles/minimax is wired in the switchboard. See [04-hosts.md](04-hosts.md).
3. **Manual sync** — 5+ files must change together when aliases/endpoints change; no generator. See [06-sync.md](06-sync.md).
